#  KrasPolHoney_bot

Telegram-бот продаж мёда небольшой краснополянской пасеки: каталог, заказ с самовывозом,
кабинет продавца и запись на дегустации.

Бэкенд рассчитан на несколько магазинов и несколько фронтендов: чат-бот Telegram и витрина
(сайт, Telegram Mini App, VK Mini App) работают с одними данными (см. «Архитектура»).

---

##  Функциональность

### Покупатель
- выбирает сорт и размер банки, количество (до 20 шт.) и оставляет комментарий;
- оформляет заказ, получает уведомления «подтверждён» → «готов к выдаче» и сообщает, когда заберёт;
- записывается на дегустацию и отвечает на приглашение кнопками «Приду» / «Не смогу».

Незавершённый заказ (черновик) один на покупателя: новый выбор закрывает прежний,
а брошенный черновик закрывается автоматически через сутки.

### Витрина: сайт, Telegram Mini App, VK Mini App
Каталог с фото и ценами открыт всем по адресу витрины. Внутри Telegram (кнопка меню бота «Магазин»
или «🛍 Витрина» в главном меню) и внутри ВКонтакте (приложение сообщества) покупатель там же
оформляет заказ и смотрит «Мои заказы».
Заказ из витрины приходит продавцу обычной карточкой в служебный Telegram-чат, дальше — как заказ из бота:
статусы приходят покупателю в чат бота (Telegram) или в сообщения от сообщества (VK), на витрине
видны в «Мои заказы». Продавцу в карточке — ссылка на профиль VK покупателя, чтобы связаться.
В обычном браузере оформить заказ нельзя — кнопки ведут в Telegram и во ВКонтакте.

### Менеджер
Работает в одном магазине и видит только его товары, заказы и статистику:
- добавляет товары с фото и цены по размерам, снимает товары с продажи;
- подтверждает, отклоняет и выдаёт заказы — в служебном чате магазина или в «Мои заказы»;
- видит статистику: продажи по сортам, новые / в работе / выданные заказы, лист ожидания и ответы на дегустацию;
- назначает дату дегустации — приглашение уходит всем из листа ожидания магазина.

Служебный чат магазина (группа продавцов) получает новые заказы и может ими управлять —
но только заказами своего магазина.

### Владелец платформы (`OWNER_ID`)
Всё, что может менеджер, во всех магазинах, плюс управление менеджерами:
- `/managers` — список менеджеров (с магазином) и кнопки «снять»;
- `/manager_add @username` или `/manager_add <Telegram ID>` — назначить менеджером магазина-витрины;
- `/manager_add @username slug-магазина` — назначить менеджером другого магазина.

Человек должен хотя бы раз нажать `/start`.

### Статусы заказа

```
Черновик → Создан → В работе → Готов к выдаче → Покупатель сообщил дату → Выдан
              └────────┴────────────┴──→ Отклонён            Черновик → Просрочен
```
Разрешённые переходы описаны в `bot/domain/order_flow.py` — любое другое действие (повторный клик,
старая кнопка) бот отклоняет.

## 🏗 Архитектура

- **Bot**: Python 3.12 (python-telegram-bot 22, SQLAlchemy 2 async)
- **API**: FastAPI (`bot/api/`, тот же образ и те же `services/`, контейнер `api_honey`)
- **Web**: React + Vite + TypeScript (`web/`), раздаёт nginx в контейнере `web_honey`
- **Database**: PostgreSQL 15 + PostGIS
- **Logs**: JSON-логи + FastAPI Log Viewer
- **Proxy**: Nginx Gateway (внешний, HTTPS)

```
Telegram ─► bot_honey ──┐
                        ├─► services/ ─► PostgreSQL
браузер / TG и VK Mini App ─► web_honey (nginx) ─► /api ─► api_honey ──┘

уведомления: очередь notifications ─► Telegram (бот) / VK (сообщество, messages.send)
```

Слои: `domain/` (правила, без БД и Telegram) → `services/` (бизнес-операции над БД, без Telegram) →
адаптеры: чат-бот (`handlers/`, `utils/telegram_*`) и HTTP API (`api/`). Новый фронтенд — это новый
адаптер поверх тех же `services/`.

**Вход на витрину.** Пароля нет: Telegram подписывает данные пользователя Mini App (`initData`) ключом,
производным от токена бота (`api/telegram_auth.py`), VK — параметры запуска защищённым ключом
приложения (`api/vk_auth.py`). API проверяет подпись и находит или создаёт пользователя; из Telegram —
того же, что в боте. Во фронтенде платформа (Telegram / VK / браузер) выбирается при старте
(`web/src/platform.ts`), экраны от неё не зависят.

**Доставка уведомлений** — адаптер на платформу (`utils/telegram_delivery.py`, `utils/vk_delivery.py`)
за общим фасадом `utils/delivery.py`: каждая строка очереди уходит своему адаптеру.

**Магазины.** `shops` — продавцы платформы; у магазина точки выдачи с координатами (`shop_locations`)
и служебные каналы в платформах (`shop_channels`: например, Telegram-группа продавцов).
Товары, заказы, дегустации и зоны доставки принадлежат магазину; менеджер — одному магазину (`users.shop_id`).
`STOREFRONT_SHOP` в `.env` — slug магазина-витрины: бот показывает только его каталог.
Пусто — режим маркетплейса (каталог всех магазинов).

**Пользователи.** Внутри системы человек — `users.id`. Аккаунты в платформах — `user_identities`
(`telegram`, `vk`, `max`, `web`): один человек может заходить из разных мест.

**Уведомления** идут через очередь `notifications` (outbox): сообщение записывается в той же транзакции,
что и событие, и сразу отправляется; если Telegram не ответил — бот повторяет с паузами до ~5 часов.
Формат нейтральный (`domain/messages.py`: HTML-подмножество и кнопки), Telegram-адаптер лишь отображает его.

**Фото товаров** — в собственном хранилище (`MEDIA_DIR`, том `bot_media_honey`); в БД — ключ файла,
Telegram `file_id` — только кэш. Сайт и другие платформы берут тот же файл.

## Инфраструктура данных (RAID5)

Все критически важные данные проекта хранятся вне контейнеров на RAID5-массиве хоста для обеспечения отказоустойчивости и удобства бэкапа.

### Пути на хосте и права доступа
Перед запуском проекта необходимо создать директории и настроить владельцев:

| Сервис | Путь на хосте | UID:GID | Описание |
| :--- | :--- | :--- | :--- |
| **db_honey** | `/data/easysochi/postgres_honey` | `999:999` | Данные PostgreSQL |
| **bot_honey** | `/data/easysochi/media_honey` | `1000:1000` | Фото товаров (источник истины, входит в бэкап) |
| **logs** | `/data/easysochi/logs_honey` | `1000:1000` | Логи бота для вьюера |

### Команды для подготовки окружения
```bash
sudo mkdir -p /data/easysochi/{postgres_honey,media_honey,logs_honey}
sudo chown -R 999:999 /data/easysochi/postgres_honey
sudo chown -R 1000:1000 /data/easysochi/media_honey /data/easysochi/logs_honey
sudo chmod -R 750 /data/easysochi/
```

## 🚀 Быстрый запуск

> Убедитесь, что установлены Docker и Docker Compose

1. Клонируйте репозиторий:
```bash
git clone git@github.com:nboravlev/EasySochi_honey_bot.git
```
2. Создайте файл `.env` на основе примера:
```bash
cp .env.example .env

```
3. Примените миграции (создают таблицы и справочники статусов, ролей, размеров):

```bash
docker compose up -d --build db_honey
docker compose run --rm bot_honey alembic upgrade head
```

4. Запустите приложение

```
docker compose up -d --build
```

Код бота берётся из образа, поэтому после изменений нужен `--build`.

**Выкатка обновлений, мониторинг, бэкапы, восстановление после аварии — в [OPERATIONS.md](OPERATIONS.md).**
Миграции при обновлении применяются той же командой `alembic upgrade head`.

### Доступ к БД и лог-вьюеру

Порты PostgreSQL и лог-вьюера по умолчанию опубликованы только на `127.0.0.1` сервера:
у вьюера нет авторизации, а в логах есть персональные данные. Подключаться через SSH-туннель:

```bash
ssh -L 5335:127.0.0.1:5335 -L 8080:127.0.0.1:8080 user@server
```

Открыть порт наружу можно явно: `POSTGRES_BIND=0.0.0.0` / `LOG_VIEWER_BIND=0.0.0.0` в `.env`.

## Разработка

Все команды — из каталога `bot/`:

```bash
pip install -r requirements.txt -r requirements-dev.txt
ruff check .
pytest                                   # юнит-тесты
RUN_DB_TESTS=1 pytest tests/integration tests/e2e  # на временной PostgreSQL после alembic upgrade head (e2e очищает таблицы!)
```

Время в БД хранится в UTC (`timestamptz`), пользователю показывается по Москве (`utils/timeutils.py`).

Добавить или обновить зависимость: поправить `requirements.in` (или `requirements-dev.in`) и пересобрать lock:

```bash
pip-compile --strip-extras requirements.in
```

Новая миграция (нужна запущенная БД и переменные `POSTGRES_*`/`DB_HOST`):

```bash
alembic revision --autogenerate -m "описание"
```

### Витрина локально

API (из `bot/`, нужна база): `uvicorn api.main:app --reload --port 8000`, документация — http://localhost:8000/api/docs.
Фронтенд (из `web/`, Node 22):

```bash
npm ci
npm run dev          # http://localhost:5173, /api и /media проксируются на :8000
npm run typecheck && npm test && npm run build
```

В обычном браузере витрина работает на просмотр. Чтобы проверить заказ без Telegram, откройте страницу
с параметрами запуска Mini App: `http://localhost:5173/#tgWebAppData=<initData>` — подписанную
`initData` для своего `BOT_TOKEN` даёт `api.telegram_auth.sign_init_data` (так сделано в `tests/e2e/test_api.py`).
Режим VK: `http://localhost:5173/?vk_app_id=…&vk_user_id=…&vk_ts=…&sign=…` — параметры подписывает
`api.vk_auth.sign_launch_params` с вашим `VK_APP_SECRET` (`tests/e2e/test_vk.py`); вне VK вызовы VK Bridge
пропускаются, заказ оформляется кнопкой на странице.

Логи: `bot_structured.log` (бот) и `api_structured.log` (API) в `LOG_DIR` — JSON по строке на запись, ротация по 10 МБ × 5 файлов;
предупреждения и ошибки дублируются в `docker logs`. В коде:
`structured_logger.info("текст", action="order_created", order_id=..., context={...})` —
`user_id`/`chat_id`/`update_id` текущего апдейта добавляются автоматически.

## Безопасность

 * Конфиденциальные данные (пользователи БД, токены) хранятся в переменнных .env
 * Доступ в Telegram бот регулируется ролями
 * API витрины: персональные данные и заказы — только по подписи Telegram (`initData`, срок годности
   `WEBAPP_AUTH_MAX_AGE_HOURS`); покупатель видит только свои заказы; не больше 10 заказов в час;
   в режиме витрины заказать можно только товары её магазина. Публичен только каталог.
 * Контейнер API наружу не опубликован — к нему ходит только nginx витрины по сети Docker.
